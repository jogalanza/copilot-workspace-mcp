M365 Code Analyzer MCP

Set up a Copilot Studio agent with this MCP server

Give a Copilot Studio agent (and Teams chats) the ability to list, read and write files in named code workspaces on your machine, with each chat remembering its own workspace.

Overview

Copilot Studio cannot reach localhost, so the server is exposed through a dev tunnel. The agent talks to it through a Power Platform custom connector that carries your API key and the chat's id.

You will need

  • Node.js 22.13 or newer
  • A Copilot Studio environment where you can create agents and custom connectors
  • The Dev Tunnels CLI (devtunnel) or another HTTPS tunnel
About the screenshotsThe panels below are simplified illustrations, not real screenshots. Copilot Studio changes its menus often, so labels may differ slightly. The values you enter are the part that matters.

1Configure and start the server

npm install
Copy-Item .env.example .env
npm run new-key        # writes MCP_API_KEY into .env and prints it once - copy it

Edit .env and register the folders the agent may touch:

WORKSPACES="app=D:/Repos/my-app;docs=D:/Repos/my-docs"
DEFAULT_WORKSPACE=app
ALLOWED_ROOTS="D:/Repos"          # add_workspace may only register folders under these roots
Paths with spaces or #Wrap the whole value in double quotes. An unquoted # starts a comment and silently truncates the path.
npm run dev      # or: npm run build && npm start
curl http://localhost:8790/health

You should see a healthy response. /health is the only endpoint that does not need the API key.

2Expose it with a dev tunnel

devtunnel user login
devtunnel host -p 8790 --allow-anonymous

Copy the HTTPS host it prints, for example abc123-8790.euw.devtunnels.ms. Check it from outside:

curl https://abc123-8790.euw.devtunnels.ms/health
Why anonymous?Copilot Studio cannot sign in to the tunnel itself. The tunnel is open, but every endpoint except /health still returns 401 without your MCP_API_KEY. Treat the key like a password and stop the tunnel when you are not using it.

The MCP endpoint is https://<tunnel-host>/mcp. The /mcp suffix is required.

4Add the MCP server as a tool

In the agent, go to Tools and choose Add → Model Context Protocol. This opens the MCP onboarding wizard.

4a. Fill in the server details

  1. Server name: M365 Code Analyzer MCP.
  2. Server description: Read, list and write files in named code workspaces.
  3. Server URL: https://<tunnel-host>/mcp. The /mcp suffix is required.
  4. Authentication: choose API key, set Type to Header and Header name to api-key.
  5. Choose Create.

4b. Create the connection and add the tool

  1. On the next screen choose Create new connection and paste the MCP_API_KEY value when asked.
  2. Return to the wizard and choose Add and configure (or Add to agent).
If the wizard has no way to add the conversation-id headerStep 5 needs a conversation-id input on the tool. If you cannot add it to the wizard-created tool, import docs/copilot-studio-connector.yaml as a custom connector instead (set host to your tunnel host, no https://) and add that connector to the agent. It already declares both the api-key and conversation-id headers. Without a conversation id the agent still works, but use the workspace-argument instructions in step 6.

The agent should now list the server's eight tools:

  Agent › Tools  Connected
List workspacesRegistered workspaces, default and this chat's current one
Switch workspaceBind this chat to a workspace
Current workspaceWhich workspace this chat uses and why
List filesGlob within the workspace
Read fileRead a UTF-8 text file
Write fileCreate or overwrite a text file
Add workspace / Remove workspaceRegister or unregister a folder
Tool namesThe file tools are named ws_read_file and ws_write_file on purpose. The plain names read_file and write_file clash with the agent's built-in tools, and the call never reaches this server.
Consider restricting writesTurn off Write file, Add workspace and Remove workspace if the agent should only read code. Write calls are also audited at GET /audit.

5Pass the chat's conversation id

This is what lets each chat remember its own workspace, even across server restarts.

  1. In the agent, open Tools, select the MCP server you added, and look for its Inputs.
  2. + Add input and pick conversation-id.
  3. Set the value to Custom value and enter System.Conversation.Id.
  Tool › Inputs
Input
conversation-id
Fill using
Custom value
Value
System.Conversation.Id
Do not leave it emptyWithout this input the server sees no conversation id. Every chat then shares the default workspace, or the agent has to pass workspace on every call.

6Add instructions

In the agent's Instructions field, paste:

You work with code workspaces through the "M365 Code Analyzer" tools
(list_workspaces, switch_workspace, current_workspace, list_files, ws_read_file, ws_write_file).
- Always use ws_read_file and ws_write_file for files. Never use any built-in file tool.
- At the start of a task, if the user has not named a workspace, call list_workspaces and ask which to use.
- When the user picks or changes a workspace, call switch_workspace with that alias.
- Use paths relative to the workspace root. Call list_files first if unsure of a path.
- Every tool reply starts with [workspace: <alias>]. If that is not the workspace the user expects, stop and ask.
- Before ws_write_file, show the user the intended change and the target path, and wait for approval.
Fallback when no conversation id is sentIf your channel does not provide a conversation id (for example Microsoft 365 Copilot declarative agents), use docs/m365-agent-instructions.md instead. It tells the agent to pass the workspace alias on every call.

7Test it

Use the Test your agent pane. A good first run proves the tools, the key, and the per-chat workspace:

  Test your agent
Which workspaces do you have?
list_workspaces → app (default), docs
I have two workspaces: app (default) and docs. Which one should I use?
docs. Show me README.md
switch_workspace {alias: "docs"}
ws_read_file {filePath: "README.md"}
[workspace: docs] README.md …

Then open a second chat and confirm it starts on the default workspace, not docs. That confirms the conversation id is working.

Watch the serverEvery tool call appears in GET /audit?limit=20 (send the api-key header). Failed reads also log a line to the server's stderr.

8Publish

  1. Choose Publish at the top right and confirm.
  2. Under Channels enable Teams and Microsoft 365 Copilot (or your target channel).
  3. Authorize or share the agent with the people who need it.

The Test pane uses the draft. Teams and other channels only see what you have published.

Optional: browser and command tools

Let the agent start your app, look at it and debug it. Both groups are off by default; enable them in .env and restart the server:

ENABLE_BROWSER=true
RUN_ALLOWED_COMMANDS="npm run dev;npm run build;npm test"
ToolWhat it does
run_command, process_output, process_stop, list_processesRun allowlisted commands; background mode for dev servers (readyText returns once the server prints e.g. "Local:").
browser_open, browser_screenshotOpen a page and capture it. The PNG is returned and saved to .screenshots/ in the workspace.
browser_text, browser_click, browser_typeRead and drive the page by CSS or text= selectors.
browser_eval, browser_logsRun JavaScript in the page; read console errors and failed requests.

After restarting the server, refresh the MCP tool in the agent so the new tools appear, enable the ones you want, and Publish. Add a line to the instructions such as: "To check the UI, start the app with run_command (background), open it with browser_open, take a browser_screenshot, and stop the process when done."

SecurityThe browser only loads localhost unless you extend BROWSER_ALLOWED_HOSTS, and page scripts from browser_eval are held to the same limit. Commands must start with an allowlisted entry and may not contain shell operators or quotes. Never allowlist node, python or powershell. Anyone with the API key can run the allowlisted commands, so keep the key private. Copilot Studio may not display the returned screenshot image; the saved file is the fallback.

On every tool call the server checks these in order and stops at the first match:

Bindings survive server restarts and expire after BINDING_TTL_DAYS (30) of inactivity. If a file is not found in the default workspace and the chat made no choice, a read searches the other workspaces and uses the single match.

When something changes

What changedWhat to do
Server code, no tool or schema changeRestart the server. No Copilot Studio action.
Workspaces, .env paths, limitsRestart the server.
Tool names, titles, descriptions or parametersRestart the server, then refresh or re-add the tool in the agent, check the tools are still enabled, and Publish.
Connector YAML (host, headers)Re-import the connector, then remove and re-add it in each agent, re-create the conversation-id input, and Publish.
Agent instructions or enabled toolsPublish. The Test pane uses the draft; channels need the publish.
New tunnel host (tunnel restarted)Update host in the connector and re-import. Use a persistent tunnel to avoid this.
API key rotatednpm run new-key, restart the server, then update the connection's key in Copilot Studio.

Troubleshooting

SymptomLikely cause and fix
"Name clash with built-in read_file", or reads always say "file not found"An old build or cached tool list is registering read_file. Restart the server, refresh the tool, publish. Confirm the instructions say ws_read_file.
401 UnauthorizedWrong or missing key. The connection must send header api-key. Re-create the connection with the current MCP_API_KEY.
Tools never load or time outTunnel is down, or the host in the connector is stale. Test https://<host>/health. The URL must end in /mcp.
Every chat uses the same workspaceThe conversation-id input is missing or empty. Set it to System.Conversation.Id (step 5).
"File not found" for a file that existsWrong workspace. Ask the agent to run current_workspace. Use paths relative to the workspace root, no quotes.
"File not found in the default workspace … exists in: a, b"The file is in several workspaces. Tell the agent which one, or switch first.
Workspace path looks cut off at startupAn unquoted # in .env. Wrap the whole value in double quotes.
Server will not startMCP_API_KEY is empty. Run npm run new-key.
Agent writes to the wrong placeTighten instructions to require confirmation of workspace and path, or disable the write tool.
